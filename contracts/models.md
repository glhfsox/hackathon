## CanonicalRequest

The internal format every check sees. Vendor JSON never gets past the adapter.

| Field | Type | Notes |
|-------|------|-------|
| `request_id` | str (uuid4) | Generated by the layer and shared by all audit records of this request |
| `caller_id` | str | Policy caller id resolved from the API key |
| `model` | str | Requested model name |
| `checkpoint` | Checkpoint | Set by the pipeline |
| `messages` | list[Message] | Full conversation |
| `tools` | list[ToolDef] | Tools the agent offered to the model |
| `reply` | Message \| null | Upstream reply. Set only at `tool_call` / `output` |

**Message**

| Field | Type | Notes |
|-------|------|-------|
| `role` | `system` \| `user` \| `assistant` \| `tool` | |
| `content` | str \| null | |
| `tool_calls` | list[ToolCall] | Assistant only |
| `tool_call_id` | str \| null | Tool only |

**ToolCall** has the fields `id: str`, `name: str` and `arguments: dict`. Arguments are parsed from the OpenAI JSON string.

**ToolDef** has the fields `name: str`, `description: str` and `parameters: dict` (JSON Schema).

## CheckResult

What every check returns.

| Field | Type | Notes |
|-------|------|-------|
| `check` | str | Check id, e.g. `pii_secrets` |
| `checkpoint` | Checkpoint | |
| `verdict` | `allow` \| `redact` \| `block` \| `error` | Raw check opinion, before the policy mode is applied |
| `action` | Action | Final action after the mode mapping (architecture §4) |
| `score` | float 0..1 | 1.0 for deterministic rule hits, 0.0 for allow |
| `reason` | str | Human-readable, shown in refusals and the UI |
| `redactions` | list[Redaction] | Empty unless the verdict is `redact` |
| `latency_ms` | float | |
| `decided_by` | DecidedBy | `rules` for rule checks |

**Redaction** has the fields `kind: str` (e.g. `SSN`), `start: int`, `end: int` and `replacement: str` (e.g. `[REDACTED:SSN]`). Offsets point into the message content they belong to. `message_index: int` is `-1` for the reply.

## JudgeInput / JudgeVerdict

The interface of `core/jev.py`. It is the same for Jev and the fallback.

| JudgeInput field | Type | Notes |
|------------------|------|-------|
| `checkpoint` | Checkpoint | |
| `text` | str | Already redacted content to judge |
| `context` | str | Short summary: caller role, tool names |

| JudgeVerdict field | Type | Notes |
|--------------------|------|-------|
| `score` | float 0..1 | Risk. ≥ the policy threshold means block |
| `reason` | str | |
| `categories` | list[str] | e.g. `prompt_injection`, `hidden_instruction`, `data_exfiltration` |
| `decided_by` | `jev` \| `fallback` | |

**OPEN:** the Jev wire format. The adapter maps Jev's response onto `JudgeVerdict`.

## AuditRecord

One row per CheckResult, plus one `turn_summary` row per checkpoint, plus rows for system events. Append-only.

| Field | Type | Notes |
|-------|------|-------|
| `id` | int | Auto-increment |
| `ts` | str (ISO 8601 UTC) | |
| `request_id` | str \| null | |
| `caller_id` | str \| null | |
| `model` | str \| null | |
| `checkpoint` | Checkpoint \| null | |
| `check` | str | Check id, or a system event: `auth_failed`, `bad_request`, `upstream_unavailable`, `policy_loaded`, `policy_rejected`, `signature_feed_updated`, `signature_feed_failed`, `turn_summary` |
| `action` | Action | On `turn_summary`: the Decision action |
| `reason` | str | |
| `score` | float | On `turn_summary`: the highest check score |
| `latency_ms` | float | On `turn_summary`: the summed check latency (the overhead) |
| `decided_by` | DecidedBy | On `turn_summary`: the blocking check's, else `rules` |
| `tokens` | int | Upstream usage for this request. Recorded once, on the `turn_summary` row at `tool_call`/`output` |
| `cost` | float | `tokens / 1000 * model.price_per_1k_tokens` |
| `policy_version` | str | `version` of the policy snapshot used |

Additive (optional) fields, set on `turn_summary` rows only and null on every other row:

| Field | Type | Notes |
|-------|------|-------|
| `conversation_id` | str \| null | Short hash of `caller_id` + the first user message. Groups the steps of one agent session; two sessions of one caller with the same first user message merge |
| `step` | int \| null | Assistant messages already in the conversation, i.e. which agent step this is (0-based) |
| `messages` | int \| null | Conversation length |
| `tool_calls` | int \| null | Tool calls requested in this reply. Null at `input`/`tool_result` |
| `tools` | str \| null | Comma-joined tool names of those calls, one per call |
| `tool_calls_total` | int \| null | All tool calls in the conversation so far, this reply included |
| `prompt_tokens`, `completion_tokens` | int \| null | Upstream usage split, at `tool_call`/`output` |
| `upstream_latency_ms` | float \| null | Upstream call time, at `tool_call`/`output` |
| `overhead_ms` | float \| null | Summed check latency at this checkpoint |
| `blocked_by` | str \| null | Check id that blocked, as in Decision |

**Usage** is the pipeline's input at `tool_call`/`output`, not a wire shape: `prompt_tokens: int`, `completion_tokens: int`, `upstream_latency_ms: float | null`.
